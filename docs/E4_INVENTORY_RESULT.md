## 4. 研究决定与下一步

1. 停止当前24条件/11节点方案的扩标与训练准备；草案、所有旧数据及失败记录保留。H2依然未验证，但这套实现不再作为已确定的论文创新点。H1也没有效果证据，H3仍未获得绑定优势支持。
2. 必须承认方法设计本身的适配问题：我们给短案情设置了完整法律资格和多个例外门槛，要求的观测超出输入经常提供的范围。不能把问题全部归咎于数据或通过把unknown改成false掩盖它。
3. **下一步优先恢复CJOG基础诊断B0**：用固定Qwen3-4B、既有两罪名18条dev，先推理、不训练、不调用Flash；不查看正式test分数。拟比较原输入与显式提供原始目标人物的输入两组，各18条，最多36个生成任务。它衡量基础误差及输入对象信息的影响，绝不计作EGC组合增益。
4. B0数据包需新版本：原事实/罪名/参考刑期不改，两组共享系统指令与解码预算；目标元数据不可由刑期/法条倒推，源事实须一致。目标未匹配时不得猜名、删案或只报成功样本；记录不可用掩码，两组全18条主表和预先规定的可用子集诊断分开。既有`visible_case`和旧缓存不静默修改。
5. B0目前是**计划**，专用双组打包入口、目标可用性策略及服务器一键命令尚未实现/交付；本轮不给未经实现的运行命令。助手下一步完成这些软件和离线检查，再由用户生成本机包、私下传服务器、拉GitHub代码并运行。预计新增教师API调用0；用户当前无需再运行本次盘点或清洗。
6. 收到B0后按预先类别分析刑期误差、无依据情节及目标归属，决定是否提出较窄的证据约束方法，或更换为有完整输入的任务。B0不能验证H1/H2，18条dev不能支撑论文效果或稳健性结论；新方法原创性还需单独相关工作检索。

LAIC/PCCD/CAIL仍是原CJOG路线的保留评测资源，本轮没有测试分数。若未来引入目标字段而原benchmark无法提供，必须分别报告输入协议，不可将不同信息条件的分数直接算为方法提升。合成反事实仍只能用于机制测试。
