## 阅读全部6例输入及15份响应后的诊断

1. **绑定格式负担过重。** 4个bound拒绝首先都触发主体引用不唯一，重复的被告人称谓出现2至6次。部分响应还有空证据观测、not_mentioned却引用观测等错误。因此不能通过放宽唯一性检查便宣布问题解决，也不能在原响应中手工补跨度后冒充新的模型结果。
2. **引用和字段齐全仍会判断错误。** 唯一通过的bound案例将被追缴财物视为本人退赔，并据此否定主动到案；案情既未明确其退赔行为，也未交代到案方式。本机门控接受了模型给出的主体和极性，并未验证该证据是否支持条件。其它被拒响应还把行为叙述当如实供述、把证据目录当抓获事实。
3. **flat有修复也有新错误。** 同一案件中它识别了明确的集体抓获；另两例却将证据目录中的抓获材料、未说明到案方式的归案表述判作主动到案的反证。这两项错误不在各例唯一的回归目标中，4/6会漏掉它们，下一轮必须审阅全部8个条件。
4. **预设意见也要核验。** 电话传唤案例同时写有到机关投案，现有规范对这种混合表述的优先级不够清晰。flat与预期unknown不一致，只能先记为规范分歧，不能直接定为法律判断错误。应先明确研究操作定义，再另存版本，保留v1意见和分数。
5. **发现输入与给定罪名不一致的风险。** 家属退赔回归例的事实末尾指控罪名与数据标签不同。保留原始数据，记录为待审查问题；目前不足以判断是源数据错误还是指控与最终认定差异。该例可用于事实条件诊断，正式CJOG实验前需明确处理方案。

以上为模型辅助审阅，并非独立人工法律核验。报告只保留问题描述，原始案情与API缓存仅在本机。

## 对假设和下一步的影响

当前不支持采用bound v1扩大标注。H3尚未得到支持，复杂绑定字段本身没有体现可靠性收益；这轮也没有检验核心H2（egc对concat），不能把失败扩大为对整个EGC方向的否定。

先暂停60条新样本API标注和训练。60条输入已成功冻结（诈骗/抢劫各30），尚未标注，也未用于本轮提示修订。旧18个任务已无pending，重复原命令不会修复这7个失败输出；保留缓存，不盲目删除或重付费。

下一步计划是一次有边界的E2修订，**本回合尚未实现新代码或交付新运行命令**：

- 简化引用表达，考虑由本机提供可校验的句段ID，减少模型反复复制主体、时间和来源跨度；维持主体/事件信息可审查，不把检索定位当语义证明。
- 明确只允许有支持/反证依据的观测；没有依据时允许零观测。统一归案、证据目录、追缴及混合传唤表述的操作定义，flat与bound共享相同边界。
- 独立检查证据与条件的支持关系，避免仅靠模型自报的主体/极性就放行。不得为6个ID写特判或把关键词启发式当金标准。
- 补齐脱敏的请求失败诊断，并清楚区分任务结束、可比较覆盖率和语义审查；保留未知请求不自动重试的约束。
- 冻结新版本后，交由用户在新目录进行小额回归；检查全部条件和新增错误，再决定是否在冻结60条上比较flat/bound。遵守主记录最多两轮规范迭代的预算，持续无改善则缩小或放弃此绑定实现。
