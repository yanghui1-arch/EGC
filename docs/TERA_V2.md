# TERA v2：潜在目标人物路由与数值MBR解码（2026-10-12，已实现、未在GPU上验证）

本文记录TERA v2的动机、实现和对照边界。**这是已编码并通过离线合成检查的方案，没有真实训练/推理结果，不代表任何提升。**

## 1. 依据：v1在三个测试集上的两处结构性问题

**(a) 目标人物条件在测试时缺失。** 训练4757/4757、dev 528/528的prompt都含`target_person`，LAIC/PCCD/CAIL共1420例全部没有（见[分布审计](DISTRIBUTION_AUDIT_20260930.md)）。v1用目标人名token池化得到条件向量，缺名时改用零初始化的`missing_target`参数；训练中从未走这条分支，所以测试时TERA的路由条件实际上是一个未训练的常量。dev（有目标）上TERA相对tera_noaux降4.09%，LAIC（无目标）上相对generic仅降1.23%且区间跨零。两者一致，但不能证明因果。

**(b) 月份是按数字逐个greedy生成的。** Qwen把数字拆成单个数字token。训练标签首位数字分布为：1占31.6%（12、18、10、120…）、3占28.1%（36、30、3…）、2只占11.5%（24…）。greedy先选总概率最大的首位数字，再选条件最大的后续数字，结果几乎总是落在“1→2→结束”或“3→6→结束”。这与有效预测约97%集中在12/36/120（金标约38%）相符。每位都选最可能的数字，组合起来不一定是最可能的整数，更不是MAE最优的整数。助手只用本机已有的train标签和LAIC预测文本做了只读统计，没有新的推理。

## 2. 实现内容

| 组件 | 实现 | 位置 |
|---|---|---|
| 去目标输入包 | train/dev/test的prompt统一没有`target_person`。目标人名在案情中的字面位置只写入标签侧文件`{train,dev}.target_supervision.jsonl`，永不进入模型输入；人名后紧跟“某/X/×/*”时视为他人名（如张某某）并跳过。默认SFT损失不变，月份半权损失只作为可选消融`--balanced-sentence-loss` | `egc/correct_training.py`，版本`implicit-target-sentence-v2` |
| 潜在目标指针 | 在全部事实token上做由罪名调节的打分和softmax，加权求和得到目标向量，替代v1的显式人名池化；之后的路由（target/other/uncertain角色概率加权三路读取）不变。弱监督为`-log(指针落在目标人名token上的总质量)`，与角色交叉熵相加，权重仍为0.1 | `egc/tera_model.py`，`target_mode="inferred"` |
| 对照 | generic有相同的指针和指针损失，只缺角色路由；tera_noaux没有任何辅助损失（角色和指针都关）；direct不带模块。各组使用同一个去目标数据包。**2026-10-12按用户决定，本轮用`--arms`跳过generic** | 同上；参数量tera/generic差异仍<5% |
| 数值MBR解码 | 生成到`"sentence_months": `、且greedy下一个token是数字时，展开一棵数字树（最多3位，联合概率<1e-3的分支剪掉并记录损失质量），得到整数月数分布，取**中位数**（期望绝对误差最小）写入，并禁止紧接的数字token改写它。同一次生成同时记录greedy整数，因此一次运行就能得到MBR和原greedy两套结果 | `egc/tera_server.py`：`number_mbr`/`generate`/`greedy_view` |
| 机制诊断 | 每条预测记录指针最高的事实token；dev额外记录指针落在金标目标人名上的质量（标签只用于事后评分，不参与生成） | `routing_diagnostic` |
| 评测 | 默认依次评测LAIC/PCCD/CAIL三个测试集，也可重解码dev；兼容已保存的v1权重，用于单独测量解码的作用；输出完整集指标、greedy对照、MBR触发数，以及明确标注的事后共同有效子集 | `egc/tera_benchmark.py` |

v1的显式模式保留，只供已保存的v1权重推理使用；新训练拒绝显式目标输入，也拒绝没有去目标修订的数据包。

## 3. 要检验的问题和归因边界

1. **解码贡献（不属于模块）：** 用v1 seed42已保存权重，在同一prompt上跑MBR和greedy。greedy整数应逐例复现旧预测，这一项作为软件正确性核验。MBR带来的差异是所有组共享的解码协议效应，不能算作TERA的贡献。
2. **协议修订贡献：** direct v1（显式目标，greedy）与direct v2（无目标，同解码）比较，反映训练/测试输入一致化本身的作用。
3. **模块贡献（H5）：** 同一v2数据包、同解码条件下比较tera与tera_noaux/direct，判定标准不变，包括原定的3%门槛、完整覆盖和多seed要求。本轮跳过generic，因此即使tera胜出，也只能说明“加模块+弱监督”有用，不能说明角色路由本身有独立作用，也不能排除参数量的作用。需要做这个机制主张时，再在同一run目录用`--resume`补generic。
4. **机制：** dev上的指针目标质量只能说明“指向人名token”，不等于语义上的主体归属正确；独立审阅仍需要另外完成。

## 4. 风险与局限

- MBR中位数依赖模型对整数分布的校准。如果模型在12和36之间过度自信，改善会有限；PCCD的重刑期偏移也不是解码能解决的。
- 字面人名匹配是弱标签：34个训练案例没有字面出现（占0.7%），同名、简称、指代都没有处理。
- JSON格式失败（v1在LAIC上每组1–9例）不受解码修订影响，完整集MAE仍可能无法报告；本次没有加入受约束的JSON解码。
- LAIC已经被观察过，PCCD/CAIL的标签聚合分布也看过。解码修订的依据来自train标签和dev/LAIC预测文本，必须披露为benchmark已接触后的开发；确认性结论需要另设未使用的数据。
- 单seed先导；参数量变化很小（指针增加约3.3万参数），但不能据此说两版完全等价。

## 5. 离线验证（2026-10-12，本机CPU）

使用隔离安装的Transformers 5.17/PEFT 0.20/Torch 2.6 CPU。为绕开本机sklearn/pandas与numpy的ABI冲突，测试脚本在运行时屏蔽了这些可选依赖（不改环境，不改仓库）。全套164项离线测试通过，新增内容包括：

- 指针梯度、损失组成（tera/generic有指针监督，noaux没有）、拒绝显式目标输入、零初始化恒等、缓存与完整重算一致、参数预算；
- 用已知整数分布的脚本化LM检验：greedy为12、MBR中位数为24，数字之后的续写被阻断（不会变成240），greedy视图可以还原，缓存回滚只用负数crop；
- 在真实的微型Qwen2缓存上，数字树分布、中位数、均值和greedy路径与逐个重新前向的暴力计算一致，且回滚后续写的logits与新算的一致；
- 去目标包含有标签侧人名位置、排除“甲某某”、多测试集编排、v1权重兼容。

**这些检查不覆盖：** 真实Qwen2.5分词器上数字是否单token（推理开始时会检查，不满足立即报错）、A100上的数值表现、任何benchmark指标。
