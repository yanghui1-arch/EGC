# 上下文主体恢复：区分事实错误与引用格式

2026-09-23，依据用户关于“让模型学习补充上下文主语”和“不要太严格”的建议修订。**已实现简化协议learned-context-v2，尚未生成真实v2标注或训练数据。** v1历史失败率不能当作语义错误率。

## 判断

- 原文引用162字而工程上限160字，只是长度超限，不证明语义错误。不能为了降低failed而事后修改历史通过统计。
- 上文明确出现目标人物，后句省略主语或用指代，恢复主体是合法的上下文推理。学生输入是完整案情，因此可学习这一能力。
- 多主体场景中无充分指代依据却指定某人，才有错误归因风险。不能把公司行为、侦查机关行为、财产所属者和事件执行者混为一个subject。
- 当前“subject必须在同一短quote中”的规则会误拒上下文充分的事件，并可能选择性剔除复杂案例。该约束只是格式代理，既不充分也非必要的语义正确标准。

## 当前实现

继续使用quote/subject/relation/kind，不额外强制抄录主体证据及上下文。quote是连续原文，subject允许由完整输入facts的跨句指代、省略和别称恢复，无需逐字出现在quote或facts中。主体归属由Flash判断，不由程序根据姓名或关键词推断。确实不明时由模型选择null/uncertain，不自动补值；自动检查不强制null与uncertain联动，语义是否矛盾留给抽样复核。

取消quote最多160字、必须唯一出现、重复quote拒绝、summary最多200字、证据最多6条等硬筛；提示仍鼓励简短、最多6条和约200字摘要，共用2048输出token预算。保留完整JSON、必需字段及类型/枚举、非空keep证据/摘要、review理由及quote确实来自facts。额外字段仍视为格式错误；模型缺字段或改写引用时仍有界重试，不允许程序伪造或默认填充字段。

例如虚构输入：“甲租用了仓库。随后购入材料并加工产品。”事件证据可只引用第二句，subject输出“甲”。完整输入已包含两句，不必额外抄录上下文。模型学习从上下文得出主体。引用跨度和工程token预算须分别处理，不能把统一短长度限制当语义判断。

自动校验只验证字段、类型、引用来自原文及引用范围。是否确有指代/行为归属关系需要独立语义审阅，不能靠字符串包含关系认证。教学目标不包括预测未记载事实。

## 实验与切换

普通SFT、无主体绑定证据蒸馏、带上下文绑定蒸馏保持相同案例、原始刑期和输入；绑定字段增加监督量的混杂仍须报告，并在有信号后补预算控制。重点观察跨句省略/多主体样本的归属错误和刑期MAE，不以格式通过率代替效果。

新协议使用独立版本及data/learned_v2/annotations缓存，复用data/learned_v1/pool原6000案例/划分/真实刑期。旧76案响应不迁移、不补字段或修改状态；新轮统一用新提示标注6000案，因此旧76案会再次产生调用。旧v1验证器保留用于复核历史，生产入口已切换v2。服务器提示及来源诊断同步；字符重叠不被描述为主体准确率。
