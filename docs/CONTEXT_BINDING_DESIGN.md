# 上下文主体恢复：区分事实错误与引用格式

2026-09-23，依据用户关于“让模型学习补充上下文主语”的建议修订方法设计。**本文件是下一版协议设计，尚未实现新的标注格式或生成训练数据。** 现有v1仍使用同一quote包含subject的校验，不能将它的失败率当作语义错误率。

## 判断

- 原文引用162字而工程上限160字，只是长度超限，不证明语义错误。不能为了降低failed而事后修改历史通过统计。
- 上文明确出现目标人物，后句省略主语或用指代，恢复主体是合法的上下文推理。学生输入是完整案情，因此可学习这一能力。
- 多主体场景中无充分指代依据却指定某人，才有错误归因风险。不能把公司行为、侦查机关行为、财产所属者和事件执行者混为一个subject。
- 当前“subject必须在同一短quote中”的规则会误拒上下文充分的事件，并可能选择性剔除复杂案例。该约束只是格式代理，既不充分也非必要的语义正确标准。

## 下一版应如何监督

每条事件分别提供：事件原文、主体原文提及、支持主体归属的上下文、模型判断的主体关系。允许上述证据跨句，全部来自同一输入案情，不需要程序替模型补字段。无法确定归属时由模型明确表达不确定，不能自动将失败统一改成unknown。

例如虚构输入：“甲租用了仓库。随后购入材料并加工产品。”事件证据可只引用第二句，主体证据引用第一句，归属上下文保留两句。模型学习的是从上下文得出主体，而非在引用内机械重复姓名。引用跨度和工程token预算须分别处理，不能把统一短长度限制当语义判断。

自动校验只验证字段、类型、引用来自原文及引用范围。是否确有指代/行为归属关系需要独立语义审阅，不能靠字符串包含关系认证。教学目标不包括预测未记载事实。

## 实验与切换

普通SFT、无主体绑定证据蒸馏、带上下文绑定蒸馏保持相同案例、原始刑期和输入；绑定字段增加监督量的混杂仍须报告，并在有信号后补预算控制。重点观察跨句省略/多主体样本的归属错误和刑期MAE，不以格式通过率代替效果。

新协议必须新版本/独立缓存，保存v1负面结果；不自动迁移缺失字段、不删除已有响应、不批量提高旧重试次数。先把新格式与可复用原响应的策略实现、离线测试并记录，再给用户执行命令。当前不要继续为v1同句约束付费重试；H4仍待真实训练验证。
