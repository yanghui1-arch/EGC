## 研究问题

### 当前执行方向：H4学习证据及主体归属

用户要求直接实现训练实验、由用户执行本机清洗和服务器训练，并明确不使用`if 关键词→罪名`等强规则。基于B0的动作误归/刑期监督不足，改为可证伪的H4：**在相同原始事实、给定罪名、已知目标人物和真实刑期监督下，学习生成原文证据及主体归属是否优于常规SFT和只生成证据的SFT？** 这不等于原H2法律规则组合，当前不声称已改进原论文编码器。此前E3未支持绑定抽取优势的结果仍成立；本轮测试学生训练效果，不重写E3。

## 方法定义

对每条法律条件 c，从原始案情 x 提取原文证据跨度，并预测 s(c) ∈ {supported, refuted, unknown}。未提及是 unknown，明确反证才是 refuted。引用存在只证明可定位，不证明支持关系正确。

规则包括适用罪名、条件表达式、依赖规则、阻却规则、法律后果和来源版本。条件表达式支持 all / any / not。规则状态由自身条件、所有依赖、阻却规则状态的否定共同决定；unknown 不自动转换为否定。基础规则与修正规则共同进入生成输入。当前后果只是结构化描述，不直接强制裁剪刑期，避免把错误规则变成虚假提升。

第一阶段实现为提示输入的差异；核心比较是 egc 对 concat，检验组合本身是否有用。若证据只是增加 prompt 长度或依赖更强标注模型，必须在对照中揭示。

**候选贡献是证据与不确定性如何影响规则依赖和例外组合，不是使用法律数据、增加规则文本或调用Flash本身。** 尚未完成足以确认原创性的系统相关工作排查，EGC仍是研究假设。第一篇提供启发，不强行包装成双论文融合；四种提示的实验也不能证明已经改进原论文神经架构。

200条试标后的调整：先独立抽取主体、事件、时间、陈述来源及支持/反证跨度，再映射到条件。unknown区分未记载、归属不清和事件冲突；分析文本不能反过来充当条件真值。现有八类通用情节只是标注规范，不是真实法律规则，也不是完整量刑因素集合。独立抽取和本机映射已实现；新的后续分析生成阶段尚未实现，旧联合生成仅作为对照。

E2软件版本fact-binding-v1提供joint/flat/bound三组：旧联合提示、无分析的平面条件抽取、共享判断边界但显式绑定的观测抽取。主要比较flat/bound；joint/flat还改变了边界提示，不能把差异仅归因于删除分析。逐观测绑定不是完整事件图，来源/主体/极性仍可能被模型判错，门控并非语义正确性证明。详见[本机运行步骤](RUN_FACTS_E2.md)。

| 名称 | 输入 | 目的 |
|---|---|---|
| base | 案情 + 给定罪名 | 统一的直接生成基线 |
| rules | base + 候选规则 | 测量额外法律知识的贡献 |
| concat | rules + 三态条件和相同证据 | 控制标注信息与标注模型 |
| egc | concat + 依赖/例外组合状态 | 测量规则组合的增量贡献 |

先用同一冻结 Qwen 做 dev 小试；再使用同一 Qwen、同一训练/dev案件、训练模式、训练轮数和解码设置分别训练四个版本。用户确定小于7B全参、7B及以上LoRA：Qwen3-4B组内四个版本均全参，Qwen3-8B组内四个版本均LoRA且rank一致。主要方法增益在同模型同训练模式内比较，不能把4B全参与8B LoRA的差异归因于EGC。记录实际 prompt/output tokens、标注调用和推理时间。当前脚本记录 token 数；严格匹配上下文预算和计时分析仍需实验阶段补齐。

后续增加：去掉 unknown（三态退化两态）、去依赖、去例外、扰动证据及等长度冗余文本对照。除各模块消融外，再比较作者原始 Chain-Aware Encoding 与加入 EGC 的编码器，才能声称改善了第二篇的模型架构。四个 prompt 版本本身不构成该复现。

另外增加有/无合成分析的对照，所有方法使用相同的保留案件和训练目标。无合成分析时，仅用原始刑期监督的目标格式及入口尚需实现。concat与egc不能在教师调用次数、条件内容和证据质量上不同。先验证核心对照，再铺开消融，避免在基础问题未解决时大量训练。

主指标为刑期 MAE、RMSE、格式有效率/覆盖率，并报告逐罪名表现。缺失输出不算0月，也不能只在成功样本上声称完整集提升。CAIL 不能报告理由质量。当前字符级 ROUGE-L 只作内部诊断；论文可比 ROUGE/BLEU 必须另行对齐作者分词、字段和实现后报告。

标注效率采用Flash批处理并做模型辅助抽查。若正式报告法律标注准确率，仍需独立的人工核验样本和分歧裁决；助手抽查不能冒称人工金标准。自动关键词差异仅用于排查，不作真值。冻结标注规范后，对test盲审选定样本，不能将其反馈用于调参。开发用200例规范审计可先采用机器辅助方式推进。

诈骗/抢劫是规则工程先导范围，因为上游只公开这两类链。先导结果必须标记为两罪名子集，不能当作全12罪名提升；扩展全量规则并冻结后才做全量 EGC。LawBench 不设为本阶段主指标，避免偏离 CJOG 任务。

## 继续或停止的依据

1. 先确认 train/dev 的证据缺口确实存在，且不只是措辞差异。若主要误差是标签不一致或隐藏事实不可恢复，应重定义可证据支持的评估目标，不继续堆规则。
2. 预先设定工程门槛：在 dev 上 egc 相对 concat 的 MAE 至少降低3%，格式覆盖率不下降，人工无依据情节比例下降。这是暂定投入门槛，不是预言或统计结论；正式测试前记录最终门槛。
3. 正式比较使用至少3个训练种子；报告均值、种子间变化，以及案件成组的置信区间。当前 `compare` 是独立案件的配对 bootstrap，仅适用于去重后的案件，不包含训练种子不确定性。
4. 若 egc 只优于 base 而不优于 concat，不能归因于组合创新；若扩展多次后 dev 仍无增益，应停止该方向，明确报告不适合。
