## 3. 已实现的部分规则图

文件为`configs/rules_e4_draft.json`，共24个条件、11个规则节点；复用现有三态组合器，不新增神经模型。所有规则均为`draft`、`reviewer=null`，没有冒充人工法律审核。既有默认校验会拒绝把它作为正式批准规则；离线机制验证显式允许草案，不需要用户现在批准或签名。

| 子图 | 本轮形式化范围 | 检验的组合机制 |
|---|---|---|
| 一般自首：5节点 | 主要事实及相关供述要求；投案后逃跑；翻供后是否判前恢复；从宽与较轻犯罪免除处罚的可能性 | 例外和例外的消除，状态向下游后果传播 |
| 诈骗第三条：2节点 | 适用范围、认罪悔罪为前提，全部判前退赔或对应被害人谅解两条备选路径 | 前置规则＋OR组合，不覆盖第三条全部五种路径 |
| 抢劫入户：2节点 | 合格的户、入户前犯罪目的、相关行为在户内；允许入户后临时起意的排除 | 情节构成与排除路径 |
| 抢劫公共交通工具：2节点 | 工具类别、运营、发生方式及被害人范围；小型出租车排除 | 多条件联合与例外未知传播 |

这是一种保守的研究形式化，不是法院对具体案件的结论。每个子图都有明确法律适用门控；未核验时期、地域或条款范围时为unknown。不能让教师从原刑期、标签或参考理由补出适用结论。

后果只表示可考虑的法律路径或情节资格，不计算具体刑期。可从宽不等于必须减刑；可免罚不等于输出零月。一个已覆盖路径refuted，不表示所有未编码路径都不成立。入户和公交子图也不覆盖全部抢劫加重情节。

## 4. E3标注与法律条件之间的缺口

| E3条件 | 为什么不能直接复用成法律结论 |
|---|---|
| 主动到案 | 研究操作定义未覆盖所有视为投案情形，也没有投案后逃跑与时点信息 |
| 如实供述 | 需要目标罪行/主要事实范围，共同犯罪及身份信息要求，翻供和恢复时间 |
| 退赔 | E3允许部分退赔；诈骗第三条对应路径要求全额及一审宣判前时点 |
| 谅解 | 要复核目标人物、被害人和罪行范围；文书名称不等于内容 |
| 前科 | 不等于累犯；刑罚类别、前后罪过、年龄、执行/释放与再犯间隔等仍未齐全，本轮不实现累犯推断 |
| 未成年 | 未给出责任年龄及适用版本的完整判断，本轮不接入年龄量刑规则 |
| 次要作用 | 需确认共同犯罪及目标主体，不能由受雇或参与推断；本轮尚未接入从犯规则 |

E4使用新的条件ID，旧E3状态不会自动填入新条件，旧缓存和规范不改。法律适用门控还需要独立的来源核验表，不是让纯案情API凭空判断法律版本。真实E4条件标注、来源表与快照任务构建尚未实现；本轮不交付付费命令。

## 5. 软件验证与实验计划

新增6项虚构样例测试，完整套件102项通过：草案拒绝正式加载、全unknown不自动变成立；自首翻供例外及恢复对下游的影响；旧E3条件不能满足更强条件；诈骗路径的前置与备选条件；出租车例外及入户意图缺失；concat/egc除计算轨迹外具有相同输入。它们验证程序行为，不验证法律标注准确率或benchmark效果。

接下来分三步，以下是计划，不是已运行实验：

1. **E4可观测性核查，先不调用API。** 只用两罪名train材料拟定小型固定审查表，逐项区分源事实可见、法律版本待核和输入无法支持。记录能触发依赖/例外的案件数和unknown原因，不为凑触发数补事实，不用dev/test标签调条件。如果几乎全为unknown或没有依赖/例外触发，先调整可验证任务或数据来源，不投入大规模标注和训练。
2. **冻结源表、条件与公平输入。** 使用同一批案件、同一份条件证据和相同规则给concat/egc，仅egc增加组合轨迹。base/rules为辅助对照。还需实际prompt token计量与等长度冗余文本对照，避免额外token解释增益。规则不直接读取真值刑期；新增目标主体或地域/日期信息时四组必须同样可见。
3. **E5服务器冻结模型小试。** 准备好完整任务包后，用户用Qwen3-4B先推理，不先训练。18条dev只作工程先导，报告逐案输出、失败覆盖、MAE/RMSE、实际规则触发、token/时间，不凭微小均值差宣称统计显著。先导最多两个预先记录的修订轮次。benchmark仍是冻结后LAIC两罪名子集主测、PCCD和CAIL补测，不能称全12罪名提升；三种子训练和原论文编码器复现是后续阶段。

核心H2仍是相同证据下egc能否优于concat。本轮把研究重点从抽取器复杂度移回有来源的依赖/例外机制，没有增加“已经提升”的结论。当前无需重跑清洗、API或服务器；下一步是上方新增的零API盘点命令。
