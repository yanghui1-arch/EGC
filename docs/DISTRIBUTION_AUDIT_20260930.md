# 训练集与LAIC/PCCD/CAIL分布诊断（2026-09-30）

用户确认比较三个正式测试集；direct/generic/tera_noaux/tera是四种模型，不是四份测试数据。以下以实际训练实验包为准，开发集仅作参照。

结论：训练数据/输入协议值得优先排查，但不能把当前LAIC结果简单归因于罪名或刑期边际分布。LAIC与训练集这两项分布接近，PCCD则明显偏向更重刑期。更直接的协议问题是训练/dev全部提供target_person，而三个测试集全部不提供。TERA的缺目标分支未被训练样本覆盖；它是高优先级机制假设，尚不是实验证实的失败原因。

## 比重采样更优先的两个问题

**1. 目标人物输入协议失配。** 实际训练4757/4757、dev528/528有target_person，三个测试集1420/1420没有该字段，实际规范prompt也核验一致。[tera_model.py](../egc/tera_model.py)在无目标时使用missing_target参数；它初始化为零，当前所有训练例走显式目标分支，因此缺目标路径没有获得训练案例覆盖。generic与TERA都受此影响；direct也从“有目标字段”迁移到“无目标字段”，但没有新增的这条条件分支。主干仍可能从案情理解被告，这不等于模型完全看不到人物信息。该协议漏洞应该在实现时更早检查；本轮确认输入/代码路径事实，不能据此确定造成多少MAE损失。

**2. 数值预测集中远高于训练标签集中。** 训练只有37.99%的真实标签为12/36/120月，LAIC为37.83%，但LAIC上四组有效预测约96.98%—97.91%落在三值，TERA为97.57%。dev也存在类似现象，故缺目标测试分支不能解释全部问题。仅把训练刑期边际“调得像LAIC”，无法由这些统计推出它会消除模型集中预测。

辅助监督也偏斜：已对齐且有标签的句段中target14453（92.43%）、other934（5.97%）、uncertain249（1.59%）；另有16630个未标注或冲突句段，不参与该辅助损失。这是自动对齐分布，不是语义准确率。它提示主体区分训练信号不足的可能性，并未证明给少数角色增加权重就会提高刑期指标。

## 其他质量边界

- 训练与dev/三个测试集的规范化完整事实精确交集均为0；没有重新证明语义级或原案级独立。
- LAIC内部存在两组各2条完全相同的规范化事实，均同罪名同月份（失火6月、过失致人死亡14月）。官方1200例评分保留；今后配对置信区间应按原案/规范事实分组，之前案例独立bootstrap只能作近似诊断。本轮没有回改先前区间。
- CAIL有5/120=4.17%的零月标签，训练为0；零月的原始刑种含义尚未复核，不能猜成某种刑罚或为了匹配而制造零月训练样本。
- 训练/dev reference无法院理由，SFT reasoning是Flash摘要；LAIC缺4条opinion，PCCD齐全，CAIL全部无opinion。文本目标来源不同，不能把字符ROUGE当统一官方法律推理质量指标。
- 本轮按用户要求查看了PCCD和CAIL的聚合标签分布，因此它们不再是“标签完全未看”的最终盲测；尚未运行本轮模型在它们上的推理，也未据分布改变训练数据。必须区分这两件事。

## 后续实验建议（尚未实现/运行）

先修正训练与部署输入条件的覆盖，优先在train/dev设计“提供目标／不提供目标”的配对诊断；若要新增训练，令训练覆盖缺目标场景，例如训练侧目标字段遮蔽，并只根据开发集选择比例。不要从测试判决理由/刑期反推目标人物填入模型；若做目标识别，只能用实际可用输入并单独验证。

之后再评估数据覆盖与采样：从允许的训练源补充有真实标签的长文、较长刑期和主体关系更丰富的案例，保持案件去重与标签来源；只有可靠逐被告刑期标签时才能纳入多被告训练。采样或损失权重在训练/开发集确定，不能直接拟合本次三个测试标签直方图。训练/测试预处理一致且模型选择隔离测试数据的原则见[scikit-learn官方说明](https://scikit-learn.org/stable/common_pitfalls.html)。

如果更换数据，direct与TERA必须同时使用同一新数据和相同训练预算；先做数据旧/新×方法direct/TERA的对照，判断是数据改善还是模块增益，generic/noaux再按原机制验证要求补齐。本轮未承诺提升或修改现有评分；现有seed43/44结果继续保留并验收。用于进一步开发后，后续确认性结论需要另有未使用的独立评测数据或明确报告benchmark适配设定。
